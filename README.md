## О проекте

Task Manager — backend-приложение для организации работы над проектами и задачами.

Приложение позволяет пользователям регистрироваться, авторизовываться, создавать проекты, управлять задачами и получать уведомления о выполненных действиях.

Система построена на FastAPI, использует PostgreSQL для хранения данных и Celery с Redis для выполнения фоновых задач.

Реализована система разграничения доступа по ролям, защищённые API-маршруты и автоматическая проверка данных.

## Реализованные возможности

### Пользователи и авторизация
- Регистрация по имени, email и паролю.
- Хеширование паролей перед сохранением.
- Авторизация с использованием OAuth2 Password Flow.
- Выдача JWT-токенов.
- Получение информации о текущем пользователе.
- Ограничение частоты запросов авторизации.

### Управление проектами
- Создание проектов.
- Просмотр списка проектов.
- Получение информации о проекте.
- Привязка проектов к владельцу.
- Защита данных от доступа других пользователей.

### Управление задачами
- Создание задач внутри проектов.
- Изменение информации и статуса задачи.
- Удаление задач.
- Поддержка статусов `todo`, `in_progress`, `done`.

### Уведомления
- Автоматическое создание фоновой задачи после добавления задачи проекта.
- Передача фоновых задач через Redis.
- Обработка задач отдельным Celery Worker.
- Сохранение уведомлений в PostgreSQL.
- Просмотр уведомлений и отметка прочитанных.

### Разграничение доступа
Используются две роли:

- `user` — обычный пользователь.
- `admin` — администратор.

Административные маршруты защищены проверкой роли пользователя.

## Архитектура приложения

Проект разделён на функциональные модули:

- `routers` — обработка HTTP-запросов.
- `services` — бизнес-логика.
- `schemas` — Pydantic-схемы.
- `models` — модели SQLAlchemy.
- `core` — конфигурация, безопасность и подключение к БД.
- `tasks` — фоновые задачи Celery.

Такое разделение упрощает поддержку, тестирование и дальнейшее расширение приложения.

## База данных

В приложении используется PostgreSQL.

Основные таблицы:

| Таблица | Назначение |
|---|---|
| `users` | Пользователи |
| `projects` | Проекты |
| `tasks` | Задачи |
| `notifications` | Уведомления |

Между таблицами настроены связи через внешние ключи:

- Пользователь — проекты.
- Проект — задачи.
- Пользователь — созданные задачи.
- Пользователь — уведомления.

Изменения структуры базы данных выполняются с помощью Alembic.

## Запуск проекта

### Требования

- Docker Desktop.
- Git (для клонирования репозитория).

### Запуск через Docker Compose

Клонирование репозитория:

```bash
git clone https://github.com/NKokoSik/KT7-TASK-MANAGER-BACKEND.git
cd KT7-TASK-MANAGER-BACKEND
```

Запуск приложения:

```bash
docker compose up --build -d
```

Docker Compose запускает четыре сервиса:

1. FastAPI — backend приложения.
2. PostgreSQL — база данных.
3. Redis — брокер сообщений.
4. Celery Worker — обработчик фоновых задач.

Миграции Alembic применяются при запуске API.

### Доступ к приложению

| Адрес | Назначение |
|---|---|
| http://localhost:8000 | Веб-интерфейс |
| http://localhost:8000/docs | Swagger UI |
| http://localhost:8000/health | Проверка состояния API |

Остановка приложения:

```bash
docker compose down
```

Для удаления контейнеров вместе с данными базы данных:

```bash
docker compose down -v
```

**Внимание:** параметр `-v` удаляет Docker volume с данными PostgreSQL.

## API

Основные маршруты приложения:

| Метод | Маршрут | Описание |
|---|---|---|
| POST | `/auth/register` | Регистрация |
| POST | `/auth/login` | Авторизация |
| GET | `/auth/me` | Текущий пользователь |
| POST | `/projects` | Создание проекта |
| GET | `/projects` | Список проектов |
| GET | `/projects/{project_id}` | Получение проекта |
| POST | `/projects/{project_id}/tasks` | Создание задачи |
| GET | `/projects/{project_id}/tasks` | Список задач |
| PATCH | `/projects/{project_id}/tasks/{task_id}` | Изменение задачи |
| DELETE | `/projects/{project_id}/tasks/{task_id}` | Удаление задачи |
| GET | `/notifications` | Получение уведомлений |
| PATCH | `/notifications/{notification_id}/read` | Отметка уведомления прочитанным |
| GET | `/admin/users` | Список пользователей для администратора |

Полная документация API доступна через Swagger UI по адресу `/docs`.

## Фоновые задачи Celery

При создании задачи проекта приложение отправляет сообщение в Redis.

Celery Worker получает сообщение и выполняет фоновую функцию `notifications.task_created`.

После выполнения задачи уведомление сохраняется в базе данных и становится доступно пользователю через API.

Просмотр логов Worker:

```bash
docker compose logs -f worker
```

## Тестирование

Для проверки приложения используется pytest.

Тесты проверяют:

- Работоспособность health endpoint.
- Регистрацию и авторизацию.
- Обработку повторной регистрации.
- Создание проектов.
- Создание, изменение и удаление задач.
- Проверку авторизации.
- Разграничение прав пользователя и администратора.
- Обработку отсутствующих уведомлений.

**Результат локального запуска тестов:**

```text
8 passed, 9 warnings in 1.82s
```

Все 8 тестов успешно пройдены.

Для запуска тестов в Docker:

```bash
docker compose exec -e PYTHONPATH=/code api python -m pytest -q
```

Тестовая база данных использует SQLite в памяти, поэтому отдельный экземпляр PostgreSQL для pytest не требуется.

## Развёртывание

Для публикации приложения предусмотрена конфигурация Railway.

Используются отдельные сервисы:

- API — `railway.json`.
- Celery Worker — `railway-worker.json`.
- PostgreSQL — отдельный сервис базы данных.
- Redis — отдельный сервис брокера сообщений.

Для облачного окружения задаются переменные:

```text
DATABASE_URL
REDIS_URL
SECRET_KEY
ACCESS_TOKEN_EXPIRE_MINUTES
CORS_ORIGINS_RAW
```

Для рабочего окружения используется отдельный секретный ключ и облачные подключения к базе данных и Redis.

После публикации проверяются health endpoint, документация API, регистрация, авторизация и выполнение фоновых задач.

# Task Manager

**Автор:** Никита  
**Группа:** ВР-401  
**Дисциплина:** Разработка на языке Python для Backend'а

## О проекте

Task Manager — приложение для организации работы над проектами и задачами. Пользователь может создать учётную запись, войти в систему, создавать проекты, добавлять к ним задачи, изменять их статус и просматривать уведомления.

Приложение состоит из backend на FastAPI и простой веб-страницы для работы с основными функциями. Доступ к данным пользователя защищён авторизацией: пользователь видит только собственные проекты и задачи.

## Используемые технологии

- **Python 3.12** — основной язык разработки.
- **FastAPI** — REST API.
- **PostgreSQL** — хранение данных.
- **SQLAlchemy 2** — работа с базой данных.
- **Alembic** — управление миграциями.
- **Pydantic** — проверка входных и выходных данных.
- **JWT и OAuth2 Password Flow** — авторизация.
- **Celery и Redis** — выполнение фоновых задач.
- **Docker Compose** — запуск сервисов.
- **pytest** — автоматические тесты.
- **GitHub Actions** — запуск тестов при push и pull request.

## Возможности

- Регистрация и вход по email и паролю.
- Хеширование паролей перед сохранением в базе данных.
- Выдача JWT-токена после успешного входа.
- Создание и просмотр проектов.
- Создание, изменение статуса и удаление задач.
- Разделение доступа по ролям `user` и `admin`.
- Просмотр уведомлений о создании задач.
- Ограничение количества попыток входа.
- Проверка состояния приложения через `/health`.

## Запуск проекта

### Требования

Перед запуском установите:

- Docker Desktop;
- Git (если проект клонируется из репозитория).

### Настройка

Для локального запуска файл `.env` не обязателен: Docker Compose использует безопасные для локальной разработки значения по умолчанию. При желании можно создать `.env` на основе `.env.example` и задать собственный `SECRET_KEY`. Для публикации приложения обязательно замените ключ на длинный случайный секрет.

Пример генерации ключа Python:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

### Запуск

В каталоге проекта выполните:

```bash
docker compose up --build
```

Docker Compose запустит API, PostgreSQL, Redis и Celery worker. При старте API применяются миграции Alembic.

После запуска доступны:

| Адрес | Назначение |
|---|---|
| http://localhost:8000 | Веб-интерфейс |
| http://localhost:8000/docs | Документация API (Swagger UI) |
| http://localhost:8000/health | Проверка состояния приложения |

Чтобы остановить сервисы:

```bash
docker compose down
```

Чтобы остановить сервисы и удалить данные PostgreSQL, сохранённые в Docker volume:

```bash
docker compose down -v
```

**Внимание:** команда с `-v` удаляет данные базы данных.

## Работа с API

Основные маршруты:

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/auth/register` | Регистрация пользователя |
| POST | `/auth/login` | Вход и получение JWT |
| GET | `/auth/me` | Информация о текущем пользователе |
| POST | `/projects` | Создание проекта |
| GET | `/projects` | Список проектов пользователя |
| GET | `/projects/{project_id}` | Получение проекта |
| POST | `/projects/{project_id}/tasks` | Создание задачи |
| GET | `/projects/{project_id}/tasks` | Список задач проекта |
| PATCH | `/projects/{project_id}/tasks/{task_id}` | Изменение задачи |
| DELETE | `/projects/{project_id}/tasks/{task_id}` | Удаление задачи |
| GET | `/notifications` | Список уведомлений |
| PATCH | `/notifications/{notification_id}/read` | Отметить уведомление прочитанным |
| GET | `/admin/users` | Список пользователей для администратора |

### Пример последовательности работы

1. Отправить запрос `POST /auth/register` с email, именем и паролем.
2. Выполнить вход через `POST /auth/login`. В форме OAuth2 email передаётся в поле `username`.
3. Скопировать `access_token` из ответа и передавать его в заголовке:

```text
Authorization: Bearer <access_token>
```

4. Создать проект запросом `POST /projects`.
5. Добавить задачу запросом `POST /projects/{project_id}/tasks`.
6. Проверить уведомления через `GET /notifications`.

Подробные схемы запросов и ответов доступны в Swagger UI по адресу `/docs`.

## Роли и доступ

При регистрации пользователю назначается роль `user`. Административный маршрут `GET /admin/users` доступен только пользователям с ролью `admin`.

Для локальной проверки административного доступа роль можно изменить непосредственно в PostgreSQL после регистрации пользователя:

```sql
UPDATE users
SET role = 'admin'
WHERE email = 'your-email@example.com';
```

После изменения роли войдите в приложение заново и получите новый токен.

## Фоновая задача

После создания задачи API отправляет задачу Celery в очередь Redis. Celery worker обрабатывает её и сохраняет уведомление для пользователя в таблице `notifications`.

Для просмотра работы фонового обработчика можно открыть логи worker:

```bash
docker compose logs -f worker
```

## Миграции базы данных

Миграции хранятся в каталоге `migrations/`. При запуске API выполняется команда:

```bash
alembic upgrade head
```

Для создания новой миграции после изменения моделей:

```bash
alembic revision --autogenerate -m "описание изменений"
alembic upgrade head
```

Перед применением автоматически созданную миграцию следует проверить.

## Запуск тестов

Для локального запуска тестов установите зависимости:

```bash
python -m venv .venv
```

Windows:

```powershell
.venv\Scripts\activate
```

Linux / macOS:

```bash
source .venv/bin/activate
```

Затем выполните:

```bash
pip install -r requirements.txt
pytest -q
```

Тесты используют SQLite в памяти и не требуют отдельного экземпляра PostgreSQL. В GitHub Actions тесты запускаются автоматически при отправке изменений в репозиторий и при создании pull request.

## Развёртывание на Railway

Репозиторий подготовлен для публикации на Railway. Само создание облачных сервисов требует входа в аккаунт владельца проекта и подтверждения оплаты/тарифа, поэтому публичный URL появляется только после выполнения этих шагов.

1. Создайте GitHub-репозиторий и отправьте в него содержимое этой папки.
2. В Railway создайте проект и добавьте PostgreSQL и Redis.
3. Создайте сервис API из GitHub-репозитория. Для него используйте `railway.json`.
4. В Variables сервиса API задайте:
   - `DATABASE_URL` — переменную подключения Railway PostgreSQL (если Railway предоставляет `DATABASE_URL`, проверьте, что она доступна сервису API);
   - `REDIS_URL` — переменную подключения Railway Redis;
   - `SECRET_KEY` — длинный случайный секрет;
   - `ACCESS_TOKEN_EXPIRE_MINUTES=60`;
   - `CORS_ORIGINS_RAW` — публичный origin сайта, например `https://ваш-домен.up.railway.app`.
5. Включите публичный домен для API-сервиса.
6. Создайте второй сервис из того же репозитория для Celery Worker. В настройках сервиса укажите конфигурационный файл `railway-worker.json` и те же `DATABASE_URL`, `REDIS_URL`, `SECRET_KEY`.
7. После деплоя проверьте `https://ваш-домен/health`, затем `/docs`, регистрацию, вход и создание задачи. В логах Worker должно появиться выполнение `notifications.task_created`.

Для локальной проверки используйте Docker Compose. Для публичного деплоя не используйте локальные значения `SECRET_KEY`, `DATABASE_URL` и `REDIS_URL`.

## Проверка перед сдачей

Локально выполните:

```bash
docker compose up -d --build
docker compose exec api pytest -q
docker compose logs worker --tail 100
```

GitHub Actions запускает pytest при push/pull request в `main` или `master` и дополнительно проверяет сборку Docker-образа.

**Статус:** конфигурация проекта и CI подготовлена. Публичный деплой не считается выполненным, пока сервисы не созданы в аккаунте Railway и не проверен выданный URL.
